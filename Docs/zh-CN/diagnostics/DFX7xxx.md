# DFX7xxx —— 溯源、漂移与 lint

> 生成标记之间的区块由 `.skill/gen-diagnostics.ps1` 写入。
> 标记以下的内容全部由手工写入，并在重新生成后保留。

<a id="dfx7001"></a>

## DFX7001

<!-- generated:begin DFX7001 -->
**严重级别：** 错误 (`error`)

**消息：**

```
Asset '%s' carries no DreamFX provenance stamp: it was never generated from this source, or it was created by hand.
```

**触发位置：** `Source/DreamFXEditor/Private/Generation/DreamFXGenerator.cpp:5258`, `Source/DreamFXEditor/Private/Generation/DreamFXModuleGenerator.cpp:769`
<!-- generated:end DFX7001 -->

**原因.** 资产上没有溯源戳：它从来不是这份源码生成的，或者是手工建出来的。

**修复.** 跑一次构建。如果这个资产是手建的、而且应该保持手建，就不要让任何 `.dfs` 指向它的路径 —— 一次构建就会盖掉它。

## DFX7002

<!-- generated:begin DFX7002 -->
**严重级别：** 错误 (`error`)

**消息：**

```
Asset '%s' is stale: it was generated from a different revision of this source. Run the DreamFX build.
```

**触发位置：** `Source/DreamFXEditor/Private/Generation/DreamFXGenerator.cpp:5265`, `Source/DreamFXEditor/Private/Generation/DreamFXModuleGenerator.cpp:776`
<!-- generated:end DFX7002 -->

**原因.** 资产是照这份源码的另一个版本生成的。这就是那个没人会自己发现的情况：有人改了 `.dfs`、没重建、把两个都提交了。单跑一次构建会通过，因为构建会把它修好。

**修复.** 跑一次 DreamFX 构建，把资产和源码一起提交。

## DFX7005

<!-- generated:begin DFX7005 -->
**严重级别：** 错误 (`error`)

**消息：**

```
(built at runtime)
```

**触发位置：** `Source/DreamFXEditor/Private/Generation/DreamFXGenerator.cpp:5309`, `Source/DreamFXEditor/Private/Generation/DreamFXGenerator.cpp:5314`
<!-- generated:end DFX7005 -->

**原因.** R7 漂移。源码没变，资产也没变，但它们共同依赖的某个模块现在暴露出不同的版本 —— 也就是说，这个资产是照另一个模块建出来的，而不是这次构建会用的那个。源码和资产本身都不会说这件事，这正是戳里要记模块版本的原因。

**修复.** 重建以采纳新版本；或者用 `@<version>` 固定模块，让不匹配在调用点被报出来。默认是警告，因为一次引擎升级会同时打到所有源码，而重建就能解决；`-StrictVersions` 把它升成错误，用于发布门。

## DFX7101

<!-- generated:begin DFX7101 -->
**严重级别：** 警告 (`warning`)

**消息：**

```
Emitter '%s' simulates on the GPU but declares no FixedBounds. GPU emitters cannot compute their own bounds, so it will use a default box and may be culled unexpectedly.
```

**触发位置：** `Source/DreamFXEditor/Private/Lint/DreamFXLint.cpp:138`
<!-- generated:end DFX7101 -->

**原因.** GPU 发射器读不回自己的粒子位置去算包围盒，所以没有固定包围盒的话它会拿到一个默认盒子，镜头从某个角度看过去的瞬间它就消失了。

**修复.** 在发射器或系统上设置 `FixedBounds = box(...)`。

## DFX7102

<!-- generated:begin DFX7102 -->
**严重级别：** 警告 (`warning`)

**消息：**

```
Emitter '%s' spawns by rate ('%s') with no upper bound. Set AllocationMode = Fixed and PreAllocationCount to cap the particle count.
```

**触发位置：** `Source/DreamFXEditor/Private/Lint/DreamFXLint.cpp:151`

## DFX7106

<!-- generated:begin DFX7106 -->
**严重级别：** 信息 (`info`)

**消息：**

```
pull: %s.%s is stored on the asset and not declared in this text -- skipped. pull adds no structure.
```

**触发位置：** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1755`, `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1878`
<!-- generated:end DFX7106 -->

**原因.** 资产的存储中存有某个输入的值，而文本并没有写入这个输入。pull 只重写调用已有的字面量，别的什么都不做：添加参数会改变文本所描述的结构，那是另一种改动、归另一个负责人 —— 构建安全门（DFX8017）才决定一次重建是否会丢掉这样的值。

这个列表天生就长。引擎会为每个模块的每个输入物化一个常量，所以这些行大多是模块自身的默认值坐在存储里；在本项目的内容上，一个系统报告了 94 条，其中 8 条是有人真正调过的值。

**修复.** 当这个值是模块默认值时，什么都不用做 —— 重建会复现它、什么也不丢，这也是为什么这些行是信息而不是失败。当它是被调过的值时（就是那些 DFX8017 会拒绝保存的值），把这个输入写进文本再跑一次 pull，或者用 `decompile -NoDefaults` 导出，它会打印出模块拥有的每一个输入。无论哪种方式，下一次 pull 就有字面量可以修正了。

## DFX7107

<!-- generated:begin DFX7107 -->
**严重级别：** 信息 (`info`)

**消息：**

```
pull: '%s' already holds every value '%s' stores for the input(s) it declares (%d compared, %d not declared, %d not writable, %d withheld). No bytes written.
```

**触发位置：** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2355`

## DFX7108

<!-- generated:begin DFX7108 -->
**严重级别：** 错误 (`error`)

**消息：**

```
pull reads a .dfs and the Niagara system it names: '%s' declares a %s document.
```

**触发位置：** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:907`, `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:924`, `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:935`, `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:949`
<!-- generated:end DFX7108 -->

**原因.** pull 需要一个 Niagara 系统来读出值，它从文本自身的 `Name=`/`Root=` 取路径 —— 与一次构建使用完全相同的解析方式，这样 pull 读的就是这份文本所写的资产。它会以四种方式失败：文件声明的是 Module、Emitter 或 DynamicInput 文档而不是 System；根 token 无法解析；解析出的路径上不存在系统；或者 `-Asset=` 指定的东西不是 Niagara 系统。

**修复。** 当该资产从未构建过时，先构建文本；或者用 `-Asset=` 指定你想要的资产。注意
一次导出命名的是哪个资产：plan-v4 会把每个导出写入 `Decompiled/` 命名空间，所以一次导出命名的是它的
镜像（MIRROR）—— 拉取别人在原版里调好的值就是 `-Asset=/Game/.../NS_X`，而且这也是它唯一的
拼写方式，因为一个 `Name=` 只能指向两者之一。

## DFX7109

<!-- generated:begin DFX7109 -->
**严重级别** 警告

**消息**

```
pull: %s: %s. pull rewrites literals inside a structure both sides agree on, so nothing in this stack was addressed.
```

**触发位置** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1211`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1978`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2027`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2066`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2220`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2241`
<!-- generated:end DFX7109 -->

**原因。** pull 通过将文本中的语句与资产的节点在**同一堆栈中的同一位置**进行匹配来定位一个输入，当两者对不齐时
会拒绝整个堆栈：节点数量不同、某一侧是模块调用而另一侧是折叠的赋值序列、某个模块调用的资产并非该节点所运行的
脚本、资产的节点不携带某个 `as <name>`，或者资产根本没有某个 emitter 或堆栈。

这种拒绝本身就是特性。一个可能偏一位的对应关系会改写错误的字面量，而文本文件中错误的字面量就是静默损坏 ——
因此消息会打印双方的节点名，这同时也是再往后一行就能看到的诊断。

**修复。** 构建文本，这正是让资产与文本所描述的内容相匹配的操作，然后再 pull。当两者在结构上本就应当不同时 ——
比如一次尚未构建的编辑 —— pull 并不是处理该堆栈内取值的工具。

## DFX7111

<!-- generated:begin DFX7111 -->
**严重级别** 信息

**消息**

```
pull: %s is declared but was not written back: %s
```

**触发位置** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1081`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1655`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1795`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1966`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1994`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2049`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2085`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2108`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2122`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2253`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2274`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2289`
<!-- generated:end DFX7111 -->

**原因。** 文本声明了该输入，资产也为其存储了值，pull 却仍不会写入它。每一行都指明了具体是哪一个原因：

- 该值不是字面量 —— 一个链接、一个动态输入、一个 `hlsl { }` 块、一个 `curve { }`、一个数据接口或一个
  对象引用。改变值的模式（MODE）是一次编辑，而不是一次回写；
- 文本的值无法通过对该输入的类型检查，构建也会因同样的原因拒绝；
- 多个输入或多个参数共用一个标识符。DSL 会去掉空格、连字符并忽略大小写，所以值输入 `Scale RGB` 与对它进行
  门控的内联编辑条件 `ScaleRGB` 对本语言来说就是同一个名字。写入的值究竟指的是哪一个，由其类型决定，
  就像生成器所做的那样；pull 只在无法判断时才报告；
- 同一个参数名被存储在两个脚本中且值不同，因此引擎读取的是哪一份副本并非 pull 所能确定；
- 存储的值在本语言中没有拼写形式（一个不是 int/float/bool/2-4 个打包浮点数的结构体）；
- 该堆栈是 `OnEvent` 或 `Stage` 堆栈，v1 不予处理 —— 那些需要通过聚焦切片读取，
  是与这六个固定堆栈不同的机制。

**修复。** 每一行都指明了它自己的原因，而前两个原因关乎文本而非资产。对于共用标识符，请以不会被解读为另一个的
方式拼写想要的输入，或者改变该值，让它的类型来决定。对于事件堆栈和阶段堆栈，在 v1 中无事可做。

## DFX7113

<!-- generated:begin DFX7113 -->
**严重级别** 警告

**消息**

```
pull: %s: the asset has %s that the text does not, and the text has %s that the asset does not. The two lists line up uniquely, so -Structure writes that difference; it adds and removes lines, so it does not happen without the switch. Nothing in this stack was addressed.
```

**触发位置** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1302`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:1606`
<!-- generated:end DFX7113 -->

**原因。** 文本与资产对某个堆栈结构的描述不同，而 pull 不会写入该差异。有两种形态：

- **不带 `-Structure`** —— 差异已被定位（节点列表唯一对齐），并且被有意地不应用。
  增加或删除一行会改变模块在执行顺序中的位置，而该堆栈内的值是按位置定位的，所以整个堆栈都不动。
- **带 `-Structure`** —— 差异根本无法写入：某个模块的输入中包含数据接口或对象引用（无法根据存储中的内容
  重建该调用）、文本未声明的 `Set Parameters` 模块（从折叠中拉取一串赋值是另一种编辑）、没有记录字节范围的语句、
  与其他内容共用一行的语句，或者解析器没有记录其右花括号的堆栈。

**修复。** 消息会指明是哪一种。对于第一种，如果需要该编辑，请以 `-Structure` 重新运行。对于第二种，
先构建文本（`dfx build`），这会让两种结构一致，并让值回写可用。

## DFX7114

<!-- generated:begin DFX7114 -->
**严重级别** 警告

**消息**

```
pull: the baseline could not be used (%s), so every value this text declares was compared from scratch.
```

**触发位置** `Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2442`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2448`、`Source/DreamFXEditor/Private/WriteBack/DreamFXPull.cpp:2484`
<!-- generated:end DFX7114 -->

**原因。** 脏集合的状态，每次运行只陈述一次而不是猜测：

- **磁盘上没有基线** —— 该特性到来之后的第一次运行，或者 `Saved/DreamFX/Pull/` 下的文件被删除之后。

**修复。** 前两种无需处理：它们描述的是做了保守处理的一次运行。对于第三种，请检查
`Saved/DreamFX/Pull/` 是否可写。
