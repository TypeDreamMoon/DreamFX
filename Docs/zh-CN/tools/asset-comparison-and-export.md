# 资产比较与导出覆盖范围

`asset-diff` 将原始 Niagara 系统与其 `Decompiled/` 镜像进行比较。当任意一对存在差异、镜像或原始项无法加载、内容根目录无法解析，或任一侧编译失败时，其退出状态为非零。比较失败会单独计数，绝不会报告为 `SAME`。默认情况下，在比较前会重新编译两侧；`-NoCompile` 则明确比较其当前可用的数据，而不验证新的编译结果。

系统事实包括已编写的运行时设置，如固定 tick 计时、预热计时和计数、边界、渲染标志以及可扩展性设置。仅编辑器使用的元数据、瞬态状态、图表所有权以及派生的编译缓存均不在此配置比较范围内。现有的脚本和发射器事实仍是独立的检查项。

反编译器覆盖范围的缺口意味着导出的源代码无法复现整个资产。轻量级/无状态发射器会产生 `DFX8017` 并在导出的头文件中留下缺口；其不受支持的内容不会被替换为普通的空发射器块。Adopt 会在重建之前拒绝带有缺口的导出内容。

用户参数描述会对引号、反斜杠、换行符、回车符和制表符进行转义，以便解析导出的描述时能保留其原始文本。渲染器材质用户绑定（包括网格 `OverrideMaterials` 内的条目）会导出稳定的参数名称。其由渲染器定义的材质类型来自全新的渲染器或数组元素构造函数，而不是进程本地的 Niagara 类型注册表索引。类型不同或不可读取的绑定会被报告为覆盖范围缺口。
